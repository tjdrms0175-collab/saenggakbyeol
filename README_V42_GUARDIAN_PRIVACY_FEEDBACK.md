# 생각별 선생님 v42 — 보안 피드백 5항목 적용 기록

작성일: 2026-11-24. 기준 소스: v41. **이 문서는 개발용 검토 보고서이며 개인정보 처리방침의 법률상 확정본이 아닙니다.**

## 핵심 결론

- **Gemini API 키가 유출됐다는 증거는 현재 확인하지 못했습니다.** `GEMINI_API_KEY`라는 *환경변수 이름*이나 모델 ID가 보이는 것은 키 원문 노출과 다릅니다. 본 작업에서 검토한 공개 정적 파일과 모의 운영 응답에는 비밀 키 값이 나타나지 않았습니다. 다만 과거 공개 커밋, 실제 운영 중 네트워크 응답, 이전 로그 전체는 검증하지 못했습니다.
- **모델명은 민감한 비밀번호는 아니지만, 요청대로 공개 화면과 운영 API 응답에서 제거했습니다.** 이제 브라우저는 `Google Gemini`라는 서비스명과 연결 여부만 표시합니다. 내부 모델 우선순위(3.1 Flash-Lite → 3.5 Flash-Lite → 3.8 Flash)는 서버 내부에서 그대로 유지합니다. 서버 소스 코드·비공개 로그를 볼 수 있는 운영자까지 모델명을 숨기는 것이 아닙니다. **GitHub 저장소가 Public이면 `server.mjs`의 모델 목록은 여전히 누구나 열람할 수 있습니다.** 모델 목록을 저장소에서도 숨기고 싶다면 GitHub에서 저장소를 Private으로 전환하고, Render의 연결 및 자동 배포가 계속되는지 확인해야 합니다.
- **보호자 PIN의 근본적인 한계:** 기존에는 브라우저의 PIN 쿠키를 지운 아이가 보호자라고 체크만 해도 새 PIN을 만들 수 있었습니다. 이를 줄이기 위해 운영자가 *별도 채널로 보호자에게 제공하는 비공개 등록 코드*를 최초 설정에 추가했습니다. **그러나 재사용 가능한 등록 코드는 보호자 법적 신원 인증이나 연령 확인을 대신할 수 없습니다.** 정식 공개 배포 전에는 검증된 보호자 계정·동의 흐름 등 보다 강한 장치가 필요합니다.

## 배포 전 반드시 설정할 신규 환경변수 1개

Render 대시보드 → `saenggakbyeol` → **Environment → Edit → Add variable**:

- **KEY:** `GUARDIAN_ENROLLMENT_CODE`
- **VALUE:** 비밀번호 관리자로 생성한 **16자 이상, 예측하기 어려운 임의 문자열**. 파일, GitHub, 화면 캡처, 채팅에 올리지 마세요. 보호자에게만 앱 외부 별도 연락으로 전달합니다. (초기 소규모 시험용)

예시 형식: 영문 대소문자·숫자를 조합한 임의 24~32자리 값. **이 문서에 적힌 예시 또는 테스트용 문자열을 실제 등록 코드로 사용하지 마세요.**

이미 있는 `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, AI 이용 횟수·비용 한도 환경변수는 그대로 둡니다. 새 등록 코드가 **없거나 16자 미만이면 최초 PIN 등록이 막히도록 설계**되어 있습니다. 기존에 PIN 쿠키가 정상적으로 남은 브라우저는 기존 PIN으로 진입할 수 있습니다. 브라우저 쿠키를 삭제하면 재등록 코드가 필요합니다.

> `ANSWER_PIN_SECRET`, `APP_ACCESS_PIN` 또는 `GEMINI_API_KEY`를 바꾸면 기존 PIN 쿠키의 복호화가 실패할 수 있습니다. 비밀값을 불필요하게 회전시키지 말고, 변경이 필요하다면 기존 사용자의 PIN 재설정 안내도 준비하세요.

## GitHub/Render 실제 적용 방법

1. 현재 운영 중인 정상 버전을 백업합니다. GitHub에서 버전 이름/커밋을 기록합니다.
2. `saenggakbyeol_v42_full_github.zip`을 **압축 해제**하고 저장소 최상위에 파일들을 업로드하여 기존 파일을 교체하고 Commit합니다. 혹은 v41에 바로 덮어쓰는 경우 `saenggakbyeol_v42_patch_only.zip`의 파일만 업로드합니다.
3. Render에서 신규 환경변수 `GUARDIAN_ENROLLMENT_CODE`를 설정한 뒤 **Save, rebuild, and deploy**합니다. 순서는 함께 배포해도 됩니다.
4. Render → Deploys에서 새 커밋이 `Live`인지 확인합니다. 현재 설정된 **하루 사진 5회 제한**은 변경하지 않았습니다.
5. 앱을 일반 탭과 시크릿 탭에서 열어 학부모 모드의 최초 설정을 확인합니다. **시크릿 탭에서 등록 코드 없이 임의 PIN을 만들면 실패해야 합니다.** 보호자가 지급받은 정확한 코드를 입력하면 최초 설정이 가능합니다.
6. `https://saenggakbyeol.onrender.com/api/provider-config`는 이제 운영 환경에서 서비스 이름 및 설정 여부 외에 모델 목록/환경변수 이름이 보이지 않아야 합니다. 공개 GitHub의 `server.mjs` 내용까지 숨기려면 저장소를 **Private**으로 바꾸어야 합니다.
7. 실제 문제 질문, 단계별 힌트, JPEG/PNG/WEBP 사진, 음성 질문, 신고 접수, 학부모 모드 확인을 각각 한 번씩 시험합니다. 설정 정보를 찍은 스크린샷에 비밀키/등록 코드 원문이 나오지 않도록 주의하세요.
8. 다른 계정/개인정보가 관련된 실서비스 부하 테스트는 하지 않았으며, 자동 테스트는 모의 API와 로컬 서버만 사용했습니다.

**이번 v42에는 새로운 Supabase SQL 작업이 없습니다.** 기존 `daily_usage`, `ai_reports` 테이블은 변경하거나 삭제하지 않습니다.

## 공개 출시를 막는 미해결 운영 과제

1. 보호자 신원 확인/법정대리인 동의: 공통 비밀 등록 코드는 시범 운영용 대안일 뿐입니다.
2. 개인정보 처리방침: 실제 운영자 이름 또는 사업자 정보, 문의/삭제 이메일, 처리·보관기간, 수탁·국외 이전·삭제 절차, 미성년자 보호자 동의 프로세스를 확정해야 합니다. **`privacy.html`은 여전히 초안**입니다.
3. `ai_reports`와 `daily_usage` 자동 보관기간·삭제 작업은 구현되지 않았습니다. 기존 SQL의 권한 설정을 임의로 완화하지 마세요.
4. 초등학생이 이용하는 서비스에서 **Gemini API 약관의 연령·접근 제한 적용 여부를 공식 확인**해야 합니다. 별도 서면 승인이나 적합한 모델/제공 계약 없이 아동 대상 공개 배포를 완료했다고 판단하지 마세요. 공식 약관: https://ai.google.dev/gemini-api/terms
5. 무인증 공개 AI API는 요금 보호 제한을 두었지만, 계정 기반 접근 제어와 완전한 악용 방지는 아직 구현되지 않았습니다.

요청 출처 문서의 VPS 방화벽, SSH, OTP, 소셜 로그인, 난독화 항목은 현재 Node/Render 기반 익명 웹앱에 그대로 적용할 단계가 아니라 제외했습니다.
