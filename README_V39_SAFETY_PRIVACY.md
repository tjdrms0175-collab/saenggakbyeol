# 생각별 선생님 v39 — 보호자 비밀번호 / AI 답변 신고 / 개인정보 안내

## 배포 순서 (중요: **SQL 먼저, GitHub 나중에**)

1. Supabase `saenggakbyeol-seoul` → SQL Editor → New에서 `SUPABASE_SETUP_V39.sql` **전체 실행**. 기존 `daily_usage`, v38 사용량 기능 및 기록은 그대로 유지됩니다.
2. Supabase Table Editor에서 `ai_reports`가 생성되었는지 확인합니다. 빈 상태가 정상입니다.
3. v39 전체 ZIP을 압축 해제해 GitHub 저장소 루트에 업로드/기존 파일 교체 후 Commit합니다. ZIP 자체를 업로드하지 않습니다.
4. Render → Deploys의 새 커밋 상태 `Live` 확인. `https://saenggakbyeol.onrender.com/api/health`에서 version에 `v39-parent-reports-privacy-` 포함 확인.
5. Render Environment의 기존 `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 및 비용 제한 변수는 **그대로 유지**합니다. 새 환경변수는 필요 없습니다.
6. 새 브라우저(또는 기존 비밀번호를 설정하지 않았던 브라우저)에서 학부모 모드를 열면 기본 0000 대신 **보호자 최초 설정**이 나옵니다. 6~12자리 숫자와 확인, 보호자 확인란 선택 후 설정합니다.
7. 기존 브라우저에서 이미 변경했던 학부모 비밀번호는 그대로 사용할 수 있습니다. 학부모 모드 → 비밀번호 변경은 새 비밀번호를 6~12자리로 제한합니다.
8. AI 질문 1개로 힌트를 받아 답변 밑의 **🚩 이 답변 신고** 버튼을 눌러 사유를 선택한 뒤 전송합니다. Supabase Table Editor → `ai_reports`에 행이 생겨야 합니다. 테스트 신고라면 운영자가 행을 삭제하세요.
9. 홈페이지 하단의 **개인정보 처리 안내** 링크와 학부모 모드의 기록 삭제 기능을 확인합니다.

## 무엇이 달라졌나요?

- 더 이상 모든 기기에서 `0000`으로 보호자 화면이 열리지 않습니다.
- 처음 사용하는 브라우저는 보호자가 직접 새 비밀번호를 설정하도록 안내합니다. 연속·반복 숫자 및 6자리 미만은 거부합니다.
- 기존 쿠키에 암호화된 비밀번호가 있는 브라우저는 기존 비밀번호를 유지합니다.
- AI 생성 답변마다 **앱 내부 신고 버튼**이 생깁니다. 신고 사유만 기본 전송하며, 선택한 경우에만 AI 답변 600자 이하 첨부. 아이의 문제/사진/IP는 `ai_reports` 테이블에 기록하지 않습니다.
- 신고 API는 시간당 5회 메모리 제한, 출처 확인, 입력값 검증을 적용합니다. 신고 자체에는 Gemini를 호출하지 않습니다.
- 개인정보 안내 페이지(`/privacy.html`)와 앱 하단 링크가 추가되고, 로컬 저장소에 대한 안내 문구도 실제 동작에 맞게 고쳤습니다.
- 기존 Supabase 일일 사용량 제한, 사진, 힌트, 음성, Gemini 모델 우선순위, 5회 힌트 후 정답 확인은 유지합니다.

## 중요한 한계 (무료 정식 배포 전 미완료)

- **보호자 신원 검증 아님.** 신규 브라우저에서 아이가 스스로 비밀번호를 만들거나 사이트 데이터를 삭제하면 보호자 제한을 우회할 수 있습니다. 계정 기반 보호자 인증·법정대리인 동의는 별도 보완이 필요합니다.
- **개인정보 처리 안내는 개발 중 초안.** 운영자 이름·문의 이메일·개인정보 보관/삭제 기간·국외 전송 및 법정대리인 동의 등을 실제 운영에 맞춰 확정해야 합니다. 지금 상태로 Google Play 정식 심사에 제출하지 마세요.
- 이용량은 IP 해시로 제한하므로 같은 공유기를 쓰는 사용자끼리 공유할 수 있고, 악성 봇을 완전히 막지 못합니다.
- Supabase 신고 기록과 오래된 일별 사용량 기록은 현재 **자동 삭제되지 않습니다.** `SUPABASE_PRIVACY_CLEANUP_V39.sql`을 검토하여 운영자가 정기적으로 수동 삭제할 수 있습니다.
- 신고 접수 후 **Supabase Table Editor에서 사람이 검토**하고 status를 `reviewed` / `resolved`로 바꾸거나 문제를 개선해야 합니다. 신고 접수 기능만으로 콘텐츠 안전성 준수가 완성되지 않습니다.
- PIN 쿠키는 `ANSWER_PIN_SECRET`(설정 시), 기존 `GEMINI_API_KEY` 등의 키로 암호화되며, 키를 바꾸면 기존 브라우저 쿠키가 해독되지 않을 수 있습니다. 기존 키를 교체하기 전에 쿠키 마이그레이션을 검토하세요.
